## 🛠️ 2. Comprehensive System Architecture Phases

### 🔹 Phase 1: User Management, Authentication, and Authorization
- **Original Objective**: Implement User Management, Authentication, and Authorization
- **Gap Analysis**: Missing relational database schema, tenant isolation foundation, and proper security implementation timing
- **Augmented Architecture & Solutions**:
  - *Data Models/Schema*: 
    ```sql
    -- Tenant isolation foundation
    CREATE TABLE tenants (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        name VARCHAR(255) NOT NULL,
        subdomain VARCHAR(63) UNIQUE NOT NULL,
        status ENUM('ACTIVE', 'SUSPENDED', 'PENDING') DEFAULT 'PENDING',
        created_at TIMESTAMPTZ DEFAULT NOW(),
        updated_at TIMESTAMPTZ DEFAULT NOW()
    );

    CREATE TABLE users (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
        email VARCHAR(255) NOT NULL,
        password_hash VARCHAR(255) NOT NULL,
        role ENUM('OWNER', 'MANAGER', 'STAFF') NOT NULL,
        mfa_enabled BOOLEAN DEFAULT FALSE,
        mfa_secret VARCHAR(32),
        last_login TIMESTAMPTZ,
        failed_attempts INTEGER DEFAULT 0,
        locked_until TIMESTAMPTZ,
        created_at TIMESTAMPTZ DEFAULT NOW(),
        updated_at TIMESTAMPTZ DEFAULT NOW(),
        UNIQUE(tenant_id, email)
    );

    CREATE TABLE user_sessions (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
        token_hash VARCHAR(255) NOT NULL,
        expires_at TIMESTAMPTZ NOT NULL,
        created_at TIMESTAMPTZ DEFAULT NOW(),
        INDEX idx_expires_at (expires_at)
    );
    ```
  - *API & Event Contracts*: 
    - REST endpoints with tenant context injection
    - JWT tokens containing tenant_id claim
    - Authentication events published to `auth.events` exchange

### 🔹 Phase 2: Autonomous Pricing Engine, Inventory Sync, and Advertising Scheduler
- **Original Objective**: Develop Autonomous Pricing Engine, Inventory Sync, and Advertising Scheduler
- **Gap Analysis**: Missing message queue infrastructure, AI/ML architecture, and unrealistic timeline for three major components
- **Augmented Architecture & Solutions**:
  - *Data Models/Schema*:
    ```sql
    -- Inventory management with relational integrity
    CREATE TABLE products (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
        sku VARCHAR(100) NOT NULL,
        name VARCHAR(255) NOT NULL,
        current_price DECIMAL(10,2) NOT NULL CHECK (current_price > 0),
        cost_price DECIMAL(10,2) NOT NULL CHECK (cost_price >= 0),
        status ENUM('DRAFT', 'ACTIVE', 'DISCONTINUED', 'ARCHIVED') DEFAULT 'DRAFT',
        created_at TIMESTAMPTZ DEFAULT NOW(),
        updated_at TIMESTAMPTZ DEFAULT NOW(),
        UNIQUE(tenant_id, sku)
    );

    CREATE TABLE inventory_levels (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
        channel ENUM('FACEBOOK', 'INSTAGRAM', 'GOOGLE_SHOPPING') NOT NULL,
        quantity INTEGER NOT NULL CHECK (quantity >= 0),
        last_synced TIMESTAMPTZ,
        created_at TIMESTAMPTZ DEFAULT NOW(),
        updated_at TIMESTAMPTZ DEFAULT NOW(),
        UNIQUE(product_id, channel)
    );

    -- AI pricing models
    CREATE TABLE pricing_models (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
        version INTEGER NOT NULL,
        accuracy_score DECIMAL(5,4),
        status ENUM('TRAINING', 'ACTIVE', 'DEPRECATED') DEFAULT 'TRAINING',
        created_at TIMESTAMPTZ DEFAULT NOW(),
        UNIQUE(tenant_id, version)
    );
    ```
  - *Message Queue Architecture*:
    - RabbitMQ with `inventory.sync` queue (durable, DLQ enabled)
    - `pricing.calculations` queue with priority handling
    - `advertising.campaigns` queue with delayed messages for scheduling
    - Exponential backoff retry policies for all third-party API calls
