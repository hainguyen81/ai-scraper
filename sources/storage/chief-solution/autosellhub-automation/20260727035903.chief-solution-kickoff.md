## 2. Introduction  

### 2.1 Purpose  
This document provides a comprehensive, production‑ready architecture for the **Secure‑Auth‑Portal**. It translates the functional and non‑functional requirements from the SRS (v2.0) into a deployable, cloud‑native solution that satisfies ISO/IEC 27001, GDPR, and OWASP Top 10 security controls.

### 2.2 Scope  
The architecture covers:

* Web front‑end (React 18)  
* Micro‑service back‑end (Spring Boot 3.0)  
* Authentication & authorization services  
* MFA integration  
* Audit & reporting services  
* API gateway & rate limiting  
* Deployment, monitoring, and incident response  
* Security, compliance, and governance

### 2.3 Audience  
* Development & DevOps teams  
* QA & security teams  
* Product owners & stakeholders  
* Compliance & audit teams

### 3.2 Deployment Architecture  
* **AWS Region:** us‑east‑1  
* **VPC:** 2 AZs, 2 private subnets, 1 public subnet  
* **Compute:** ECS Fargate (or EKS) – 2–10 tasks per service, auto‑scaling on CPU > 70 %  
* **Load Balancer:** ALB (HTTPS, TLS 1.3, ACM certs, WAF, Shield)  
* **Database:** RDS PostgreSQL 15 (Multi‑AZ, encryption at rest, KMS)  
* **Secrets:** AWS Secrets Manager (JWT keys, DB creds, MFA secrets)  
* **Logging:** CloudWatch Logs → SIEM (Syslog over TLS)  
* **Monitoring:** CloudWatch Alarms, Dashboards, EventBridge → SNS → OpsGenie  
* **CI/CD:** CodePipeline → CodeBuild → ECR → ECS/Fargate  
* **IaC:** Terraform modules (VPC, ALB, ECS, RDS, IAM, WAF, CloudWatch)

## 5. Security Architecture  

| Control | Implementation |
|---------|----------------|
| **Transport** | TLS 1.3 everywhere (ALB, ECS, internal services) |
| **Authentication** | SAML 2.0 SSO, MFA via OTP provider, JWT (HS256/RS256) |
| **Authorization** | RBAC policy engine, JWT claims (`roles`, `mfa`) |
| **Secrets** | AWS Secrets Manager, KMS‑encrypted, rotation every 90 days |
| **Data at Rest** | PostgreSQL encryption (KMS), S3 encryption (SSE‑KMS) |
| **Data in Transit** | TLS 1.3, mutual TLS for internal services |
| **Logging** | CloudWatch Logs → SIEM (Syslog over TLS), audit trail in PostgreSQL |
| **Vulnerability Management** | OWASP Top 10 mitigations, dependency scanning, Snyk |
| **Incident Response** | CloudWatch Alarms → SNS → OpsGenie → Runbooks |
| **Compliance** | ISO/IEC 27001, GDPR, SOC 2 Type II (planned) |
